Mermaid Diagram

End-to-end veto algorithm

This diagram shows the full semantic-routing path as it currently makes sense architecturally: offline trigger and shadow generation, publication into rule pointers plus sidecars, runtime active-vs-shadow scoring, and the benchmark/diagnostic loop that tunes the system.

Core equations

A(a, c) = sim(phi(c), phi(E(a)))
M(a, t, c) = max over s in S(a,t) of sim(phi(c), phi(E(s)))
Delta(a, t, c) = A(a, c) - M(a, t, c)

Replace only when the active score is strong and the active-vs-shadow margin is strong. Otherwise prefer soft affordance or abstain.

How to read it

  • The offline lane creates the blocker set S(a,t) for an active target a under a trigger t.
  • The runtime lane never rediscovers all competitors from scratch. It loads the published competition set and scores the active target against those shadows.
  • The output lane makes the product bias explicit: false abstain is cheaper than harmful replace.

Current repo interpretation

  • top3 + forward_gloss is currently the better source-only seed lane.
  • Shadow support scoring is currently the strongest numeric control surface.
  • Trigger support scoring helps lightly upstream, but does not rescue the broad all_sources lane.
  • The remaining miss class is now more about semantic bridge recall than basic reverse-pack lookup.

Legend

Offline

Preparation, publication, trigger filtering, and blocker-set construction.

Runtime

Browser context, semantic lookup, context building, and score computation.

Decision

Threshold and safety gates that decide replace, soft, or abstain.

Output

DOM effect plus diagnostics emitted for debugging and product trust.

Feedback

Benchmarks, review packets, and sweeps feeding back into the offline lane.
