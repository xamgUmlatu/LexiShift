What The First Broad Sweep Should Test

The first broad sweep should answer one question cleanly:

"Within the current best source family and current exposed scoring/filtering space, what is the best en-es configuration?"

That means:
- use the current 57-case en-es suite
- use the frozen canonical bundle inputs
- keep the resource family fixed to the current canonical Kaikki / Kaikki lane
- explore the current exposed parameter space thoroughly

This first broad sweep should NOT try to answer:
- whether FreeDict is globally dead
- whether multi-source agreement should exist
- whether embeddings help
- whether trait-conditioned routing is better than a single profile

Those are later questions.

Recommended Stage Order

Stage A: broad sweep on the current canonical resource setup only

Use:
- Kaikki forward
- Kaikki reverse
- current 57-case dataset
- frozen word_package snapshot

Goal:
- find the best configuration inside the current exposed parameter/toggle space
- get a clean answer without confounding resource-family changes

This stage should be the main heavy-compute run on the PC.

Stage B: smaller resource-combination matrix after Stage A

Use the best few Stage A configs, then compare resource lanes:
- Kaikki forward + Kaikki reverse
- Kaikki forward + FreeDict reverse
- Kaikki forward + no reverse
- FreeDict forward + FreeDict reverse

Optional curiosity lane only if cheap:
- FreeDict forward + no reverse

Do NOT start with a giant cartesian product of:
- all weights/toggles
- times all resource combinations

That would make interpretation much worse.

Stage C: only after Stage A and Stage B

Then decide whether the next engineering slice should focus on:
- lexical-sense competition around cuadro
- slang/register suppression around acabar / coger
- phrase-policy around sacar
- or benchmark-label policy around review-tier cases
