# Testing Artifact Provenance

Status: current workflow standard

Generated test-output artifacts are not source of truth by filename. A file named
`*_latest` is usable only when it was generated by the live checkout or passes a
freshness check against the live checkout.

## Standard

Use this order for SRS/rulegen research and tuning decisions:

1. Inspect the live producer and consumer code paths.
2. Identify the exact producer script and direct input artifacts.
3. Regenerate when the artifact predates relevant code or input changes.
4. Validate provenance before using an existing artifact for a decision.

Artifacts that implement the standard include a top-level `provenance` block
with:

- producer script hash
- dependency script/module hashes
- input file hashes, or size/mtime for large external inputs
- git branch/head/dirty state
- command and cwd
- relevant version constants

Generated artifacts under `docs/test_outputs/` are recursively checked when
they appear as inputs to another generated artifact. This prevents a fresh
downstream report from silently relying on an old matrix/search artifact.

## Freshness Check

Run:

```bash
python3 scripts/testing/check_artifact_freshness.py \
  docs/test_outputs/srs_ja_acronym_signal_audit_latest.json
```

For a reusable handoff artifact:

```bash
python3 scripts/testing/check_artifact_freshness.py \
  docs/test_outputs/srs_ja_acronym_signal_audit_latest.json \
  --json-out docs/test_outputs/artifact_freshness_latest.json \
  --markdown-out docs/test_outputs/artifact_freshness_latest.md
```

Exit code is non-zero if any artifact is stale. Missing provenance is stale by
design.
